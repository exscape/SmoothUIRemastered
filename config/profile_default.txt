# The files we patch, and how.
#
# Every file listed is patched to the build's frame rate (build-main.py --fps: 120 or 60 for
# releases). Indented lines are settings for the file (or *) above them. Patterns are case-sensitive
# regexes matched against sprite class names, or "sprite N" for a character id (only for sprites
# without a class; not allowed under *).
# Note that sprite IDs are likely unstable, and so likely break on game updates.
#
# Settings applied for every file:
#   *
#       exclude: ^SomeSpinner$
#       speed 2: ^SomeGlow$
#
#   gameplay/gui_new/swf/example/panel_a.redswf
#       include: ^SomeClass$            Stretch, even if the safety checks say not to (exclude wins)
#       include: sprite 338
#       speed 1.5: ^OtherGlow$          Play 1.5x as fast as the original, in every build. Also 3/2;
#                                       below 1 slows down. At most build fps / the file's original
#                                       fps (2 for a 30 fps file in the 60 fps build), as frames
#                                       can't be dropped
#   gameplay/gui_new/swf/example/panel_b.redswf
#       exclude: ^SomeClass$            Never stretch
#       exclude: sprite 412
#       fix: gwent-3d-bug-fix           Fix a bug in the game's own file (one of the fixes in
#                                       smoothui/patcher/fixes/; not allowed under *). The file is written
#                                       even if it needs no rescaling
#   gameplay/gui_new/swf/example/module_c.redswf
#       source fps: 24                  The frame rate the file really plays at, where that isn't its
#                                       header's (a movie loaded into another plays at the other's rate);
#                                       it is rescaled from this rate. Not allowed under *
#
# Groups: files that only work together, so they are patched all or none:
#   group: example
#       shipped: no                     Not in the release: only the merger builds them, from the game's files
#       source fps: 24                  Settings directly under the group apply to all of its files
#       gameplay/gui_new/swf/example/module_e.redswf
#       gameplay/gui_new/swf/example/module_f.redswf
#           exclude: ^SomeClass$        A file's own settings are indented deeper
#   The merger patches a .redswf that a mod adds to a group's folder as one of the group's files, with the
#   group's settings (and those under *).
#
# A setting that matches no sprite (under *: if it matches in no file), a fix that changes nothing, or a
# setting that can't be followed fails --strict.
#
# Files that are not listed here are either:
# 1. missed by me; contact me if you think something needs to be added here
# 2. not relevant (framerate field is not used)
# 3. possibly noticeable, but not enough to be patched and cause compatibility issues
#
# Currently mainmenu falls under #3, but that may change (perhaps with an optional mod,
# which in that case will NOT be compatible with other mods that affect mainmenu .redswf files).

# The HUD. Every module is loaded into the root HUD movie (hud.redswf, 24 fps) and plays at its frame
# rate, whatever its own header says (30 for most), so all of them are rescaled from 24 fps, and only work
# together: one module left at 24 fps under a 120 fps hud.redswf plays 5x as fast.
# Left out: modules with no animation (console, subtitles, timelapse, watermark) and questfeed (never loaded).
# The merger patches any other .redswf a mod has in the group's folder (e.g. its copy of one of those, or a
# module of its own) as one of the group's files, with the settings under "group:" (every file in swf\hud\
# is a module that hud.redswf loads: see Hud.as loadModule).
# The merger builds them (from the game's files, or the copies of mods that change them); releases never ship
# them, as a HUD with some of them patched and some not plays the others 5x too fast or slow.

    shipped: no
    source fps: 24      # the root HUD movie's (hud.redswf's header says 24 too)
