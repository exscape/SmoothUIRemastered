# Patcher warnings in other mods' own code that have been checked and found harmless, for the merger.
# The tools ship this file, and the update check downloads it from the "manifests" GitHub release
# Syntax (see smoothui/mod_reviews.py):
#
# <regular expression matching the mod's folder names in full, ignoring case>:
#     <kind> <Class.method> @<hash>    as the merger's log shows it; the review stops applying when that code changes
#     <kind> <Class.method> @any       any version of that code: only for code that is harmless by design
#     leave-out <kind> <Class.method> @<hash or any>
#                                      the opposite: that warning means the mod's copy doesn't work with Smooth UI,
#                                      so the merger leaves it out as known not to work, instead of warning about it.
#                                      Tools v0.9.1 and older skip these lines (with a line in their log).
#     dont-merge <reason> <screen> [<screen> ...]
#     dont-merge <reason> all except <screen> [<screen> ...]
#                                      leave out these screens of the mod's (or all but these), whatever the warnings.
#                                      <screen> is a file name as the log shows it (panel_inventory, gwint_game) or a
#                                      group's name (hud: all of its files, including ones a mod adds). <reason> picks
#                                      the text the user is shown:
#                                        already-smooth  the copy is already smooth in the 120 fps build (it runs at 120 fps
#                                                        or more), but merging it only gives warnings or failures. Mind:
#                                                        time-based tweens don't make a screen smooth.
#                                        known-broken    merging it gives a wrong result, and it can't be made smooth. This
#                                                        includes a 60 fps screen that can't be merged cleanly.
#                                      A screen the merger can merge cleanly gets no line. Tools v0.9.1 and older skip these
#                                      lines too (with a line in their log), so the mod is treated as before for them:
#                                      NEVER add a review for a warning in a screen a dont-merge line leaves out, unless
#                                      merging that screen would be fine, as v0.9.1 would then merge it.
#
# A note should say *why* each one is harmless (or doesn't work). Warnings in the game's own code go in
# config/reviewed_warnings.txt.

# --- Ink and Iron: one folder, all screens in their own folders, or single-screen downloads
# Its ENTER_FRAME handlers re-apply the mod's look each frame: hide vanilla elements, restyle text,
# redraw its frames and put elements in place (from the current state, never by a step per frame), so
# the result is the same at any frame rate. Checked 2026-10-26, against version 0.9.1.
modInkAndIron.*:
    enter-frame-handler TopBarNew.inkTick @3cfaa6a4                  # panel_common: redraws when the tabs change
    enter-frame-handler TopBarNewGlossary.inkOnFrame @434da2c3       # panel_glossary_main: restyles every 12th frame
    enter-frame-handler MapMenu.inkOnFrame @fd85b1ea                 # panel_worldmap: frames each frame, restyle every 6th
    enter-frame-handler BlacksmithItemPanel.inkTick @085dabce        # panel_blacksmith
    enter-frame-handler ModuleBlacksmithGrid.inkSmithTick @3cb62315  # panel_blacksmith
    enter-frame-handler TransmogMenu.iaiTick @3b25ef1e               # panel_transmog
    enter-frame-handler ItemCraftingModule.inkRtFrame @897d778c      # panel_alchemy, panel_crafting: rows and craft panel
    enter-frame-handler ItemCraftingModule.inkFrame @a12d95f5        # panel_alchemy, panel_crafting: item card
    enter-frame-handler MenuCharacterDupe.inkPopFrame @3234ea0a      # panel_character_dupe: the apply/cancel popup
    enter-frame-handler SlotSkillGrid.inkHoldTick @113b3fe1          # panel_character_dupe: an arc mirroring the game's hold progress
    enter-frame-handler InventoryTabbedListModule.iaiClampTabs @268d2ba0  # panel_inventory: resets the tab icons' scale and color

# --- Expanded Buff Menu
# Its ENTER_FRAME handler lays out the cooldown icons each frame: places the layer at its anchor and the
# icons in a grid, from the current state (no counters). Its timers use getTimer() and its fades are
# GTweens, both time-based, so the result is the same at any frame rate. Checked 2026-10-28, against version 5.01Rev1.
modExpandedBuffMenu:
    enter-frame-handler HudModuleBuffs.onCooldownTick @2672af65      # hud_buffs: lays out the cooldown icons

# --- CMF Minimap Panel (an add-on for Conjunction Map Framework)
# Its ENTER_FRAME handler restyles the minimap's pins: each frame it copies every pin icon's position,
# visibility and alpha onto its own overlay, and restyles a pin only when its icon or the styles change.
# No counters, so the result is the same at any frame rate. Checked 2026-10-29, against version 2.1.0.
modCMFMinimapPanel:
    enter-frame-handler HudModuleWatermark.cmfOnFrame @ea3f9109      # hud_pickeditemsinfo: follows the minimap pins

# --- Conjunction Map Framework: known not to work
# It sets the map's frame rate itself (stage.frameRate: 60 by default, 24 to 60 by theme), and puts the old
# one back when its motion is turned off. The merged map's timelines are retimed for 120 or 60 fps, so they
# would play at the wrong speed. "@any": that is its design, whatever rate it sets. Checked 2026-10-29.
# Its three ENTER_FRAME handlers (cmfOverviewFrame, cmfPinButtonFrame, cmfThemeFrame) are harmless, but
# must NOT be reviewed while it sets the frame rate: tools v0.9.1 don't know these leave-out lines, and
# would then merge the map.
mod0000_ConjunctionMapFramework:
    leave-out sets-frame-rate MapMenu.cmfApplyMotion @any           # panel_worldmap: sets the frame rate
    leave-out sets-frame-rate MapMenu.cmfMotionRemoved @any         # panel_worldmap: puts the old one back

# --- UI Remastered: its HUD is left out
# It doesn't ship hud.redswf, so its HUD modules run at the game's 24 fps (the 11 hud_* files' own rates are not used).
# Merging would make them 120 fps, but two of its modules count fades per frame (quests: alpha += 0.16 / -= 0.24 and
# an animation += 0.08 per frame; wolf head: 0.16 / 0.1, and 0.34 / 0.25 after the radial menu), so their fades would
# run 5x too fast (about 50 ms: nearly instant). The rest of its HUD code is harmless. Checked 2026-10-29. Its other
# screens need no line: they are at 120 fps or more, which the merger keeps by itself (gwint_game and panel_common get
# our fixes only).
mod0000_UIRemasteredEdition:
    dont-merge known-broken hud
